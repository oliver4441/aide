## Service Worker Review (`public/sw.js`)

### Caching Strategy (Per Request Type)

| Request Type | Strategy | Timeout | Notes |
|--------------|----------|---------|-------|
| `/api/*` | Network-first → Cache fallback | No timeout | Best for sync data |
| Navigation | Network-first → Offline page | 3s | Falls back to `/offline.html` |
| CSS/JS/Fonts | Cache-first → Network fallback | 5s | Fast subsequent loads |
| Everything else | Stale-while-revalidate | 5s | Best UX for static assets |

### Strengths
- ✅ Proper `VERSION` tag for cache invalidation
- ✅ Offline page fallback (`/offline.html`) for navigation failures
- ✅ API caching with fallback for offline data access
- ✅ Navigation requests timeout and show offline page
- ✅ `SKIP_WAITING` message handler for updates
- ✅ Cache cleanup on activate (removes old versions)

### Potential Issues Found
- ⚠️ No caching for static assets like `/logo.jpg` in STATIC_ASSETS array (only `/`, `/offline.html`, `/manifest.webmanifest`, `/logo.jpg`)
- ⚠️ No cache for CSS/JS bundles generated by Next.js (handled by Next.js internal caching)

### Recommendations
1. Add more static assets to STATIC_ASSETS if you want them cached on install
2. The current strategy is actually good for a PWA - it caches what's essential first, then lazily caches other assets on first visit
